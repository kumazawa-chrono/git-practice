# エンジニア研修コンテンツ 要件定義書

## 1. 概要

### 1.1 目的

本プロジェクトは、Honeycome社のエンジニア研修用コンテンツを汎用的に作り直し、以下の目標を達成することを目的とする。

**「AI駆動開発全盛の時代でも、基礎力と正しい開発フローを身につけたエンジニアを育成する」**

### 1.2 背景

AIコーディング支援ツール（Cursor、GitHub Copilot、ChatGPT等）が普及する中、以下の能力が重要になっている：

1. **AIの間違いを見抜く力**
   - AIは時に「それっぽい」が誤ったコードを生成する
   - 基礎知識がないと、AIの出力が正しいか判断できない
   - 技術的な妥当性を検証できる基礎力が必要

2. **開発の正しいフローを知る**
   - 要件定義 → 設計 → 実装 → テスト → デプロイ → 運用の流れを理解
   - AIに振り回されず、目的を持ってAIを活用できる
   - 各フェーズで適切な判断ができる

3. **しっかりとした土台を作る**
   - 一度は自分の手を動かして作る経験
   - 実体験が、AIと協働する際の判断力の土台となる
   - 解像度の高い知識の地図を頭の中に作る

## 2. 現状分析

### 2.1 現状の研修体制

- GitHubでコンテンツを読み、自学してもらう形式
- Slackでの壁打ちと週1回30分の1on1で壁打ちを実施
- カテゴリ毎の演習のレビューをメンターが手動で実施
- 各カテゴリ毎の実践課題を繰り返し、最終的に応用演習で成果物を開発
- 応用演習で開発したものとプレゼンテーションを実施

### 2.2 現状の課題

| 課題 | 詳細 |
|------|------|
| 企業特化 | 現状のコンテンツは特定の企業用のため、汎用的に作り直す必要がある |
| レビューの負担 | メンターによる手動レビューのため負担が大きい |
| テストの不在 | 理解度チェックテストがなく、学習の定着度が測定できない |
| 難易度の不適切さ | 実践課題が「分かりづらい」「難しすぎる」という声がある |
| 超基礎の不足 | Gitの使い方など、超基礎的な内容が省かれている |
| AI時代への対応 | AI駆動開発など、今後のAIとの付き合い方に関する内容がない |

## 3. 改善要件

### 3.1 機能要件

#### 3.1.1 コンテンツの汎用化

- 特定企業に依存しない汎用的な内容に作り直す
- 複数のコース（Web、iOS/Android、IoT）に対応
- 初心者と2-3年経験者の両方に対応（難易度マーカーで区別）

#### 3.1.2 コースの構成

| コース | 期間 | 構成 |
|--------|------|------|
| Webエンジニアコース | 1-1.5ヶ月 | 共通基礎50% + コース別50% |
| iOS/Androidアプリエンジニアコース | 1-1.5ヶ月（Webコース後は0.5-1ヶ月） | 共通基礎50% + コース別50% |
| IoTエンジニアコース | 1-1.5ヶ月 | 共通基礎50% + コース別50% |

#### 3.1.3 レビューの自動化

- GitHub Actionsによる自動テスト実行
- 静的解析（リンター、フォーマッター）によるコード品質チェック
- AIを活用したフィードバック生成
- 手動レビューは設計やアーキテクチャに集中

#### 3.1.4 理解度チェックテスト

- 各コンテンツに理解度チェックテストを設ける
- 形式：選択式、記述式、コード記述
- 難易度：コンテンツを読めば回答できるレベル
- 可能な範囲で自動採点、間違えた問題の解説を提供

#### 3.1.5 実践課題の設計

- 段階的難易度：コンテンツを読めば回答できるレベル
- 積み上げ型：各カテゴリの課題を積み上げると応用演習の成果物になる
- 自動レビュー可能：コードの実行結果やテスト結果で判定可能な形式

#### 3.1.6 新規コンテンツの追加

- **Git基礎**: バージョン管理の超基礎
- **AI駆動開発**: Cursorを前提としたAIと協働する開発フロー
- **仕様駆動開発**: 仕様書の読み書き、要件定義の基礎

#### 3.1.7 コンテンツの充実

各コンテンツに以下を含める：
- **なぜ学ぶ必要があるのか**: 技術の必要性、実務での重要性、AI時代における重要性
- **技術の歴史的背景**: 技術の誕生、進化の過程、業界への影響
- **図や画像の活用**: Mermaid図によるアーキテクチャ図、フロー図、シーケンス図等

### 3.2 非機能要件

#### 3.2.1 運用プラットフォーム

- GitHub完結での運用を推奨
- 学習コンテンツ、実践課題、進捗管理を一元管理
- PRベースの開発フローで実践的なスキルを習得

#### 3.2.2 プログラミング言語

| 用途 | 言語 |
|------|------|
| 共通基礎 | TypeScript |
| Web フロントエンド | TypeScript (React/Next.js) |
| Web バックエンド | TypeScript (Node.js) |
| iOS ネイティブ | Swift |
| Android ネイティブ | Kotlin |
| クロスプラットフォーム | TypeScript (React Native) |
| IoT 低レベル制御 | C/C++ |
| IoT 高レベル制御 | TypeScript (Node.js) |

#### 3.2.3 学習時間

- 共通基礎: 約2-3週間（80-120時間）
- コース別: 約2-3週間（80-120時間）
- 合計: 約4-6週間（160-240時間）

#### 3.2.4 サポート体制

- メンター: 週1回30分の1on1セッション
- Slack: 質問、相談、雑談、ナレッジ共有

## 4. 対象ユーザー

### 4.1 研修生

| レベル | 対象 | 難易度マーカー |
|--------|------|----------------|
| 完全初心者 | プログラミング未経験者 | [基礎] |
| 若手エンジニア | 2-3年程度のキャリアがある方 | [中級] |
| 両方 | 両方のレベルで挑戦可能 | [応用] |

### 4.2 メンター

- 研修生の質問に回答、学習の方向性をサポート
- 実践課題のPRをレビュー、フィードバック提供
- 進捗管理、モチベーション維持をサポート

## 6. 成功指標

### 6.1 技術的な理解度

- プロダクト開発の各フェーズで必要な技術を説明できる
- 適切な技術選定の判断ができる
- AIの出力が正しいか判断できる

### 6.2 実装能力

- 基本的なアプリケーションを設計・実装できる
- テストを書ける
- デプロイ・運用ができる

### 6.3 チーム開発能力

- Gitを使った協働開発ができる
- コードレビューができる
- 技術的な議論に参加できる
