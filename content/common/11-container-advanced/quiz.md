### 【基礎】OS・プロセス

#### Q1. プロセスとプログラムの違いについて、正しい説明はどれですか？

- A) プロセスは静的なファイル、プログラムは動的な実行単位
- B) プロセスは動的な実行単位、プログラムは静的なファイル
- C) プロセスとプログラムは同じもの
- D) プロセスはカーネルの一部

<details>
<summary>回答と解説</summary>

**正解: B**

- **プログラム**: ディスク上の実行可能ファイル（静的）
- **プロセス**: メモリ上で実行中のプログラム（動的）

プログラムを実行すると、OSがメモリ上にプロセスを作成します。

</details>

---

#### Q2. Linuxの名前空間（Namespace）がコンテナで使われる主な目的は何ですか？

- A) パフォーマンスを向上させる
- B) リソースを他のプロセスから分離する
- C) ネットワーク通信を暗号化する
- D) ファイルを圧縮する

<details>
<summary>回答と解説</summary>

**正解: B**

名前空間は、プロセスが見えるリソース（PID、ネットワーク、ファイルシステム等）を分離する仕組みです。コンテナはこの機能を使って、他のコンテナやホストから隔離された環境を作っています。

</details>

---

#### Q3. cgroupsの主な役割は何ですか？

- A) プロセスの見え方を分離する
- B) プロセスのリソース使用量を制限する
- C) コンテナイメージをビルドする
- D) ネットワーク通信を管理する

<details>
<summary>回答と解説</summary>

**正解: B**

cgroupsは、CPU、メモリ、I/O等のリソース使用量を制限・管理する仕組みです。

- **名前空間**: リソースの見え方を分離
- **cgroups**: リソースの使用量を制限

コンテナは両方を組み合わせて実現されています。

</details>

### 【基礎】仮想化技術

#### Q4. 仮想マシン（VM）と比較したコンテナの特徴として、正しいものはどれですか？

- A) より強い分離レベルを提供する
- B) 起動時間が長い
- C) カーネルを共有するため軽量
- D) 各コンテナに専用OSが必要

<details>
<summary>回答と解説</summary>

**正解: C**

コンテナはホストOSのカーネルを共有するため：
- 起動時間が短い（秒単位）
- イメージサイズが小さい（MB単位）
- リソース効率が高い

一方、VMは完全なOS（ゲストOS）を持つため分離レベルは高いですが、オーバーヘッドも大きくなります。

</details>

#### Q5. コンテナイメージのレイヤー構造について、正しい説明はどれですか？

- A) 各レイヤーは書き込み可能
- B) レイヤーは再利用されない
- C) 各レイヤーは読み取り専用で、コンテナ起動時に書き込み可能レイヤーが追加される
- D) レイヤーは1つのイメージにつき1つだけ

<details>
<summary>回答と解説</summary>

**正解: C**

コンテナイメージは複数の読み取り専用レイヤーで構成されています。
- Dockerfileの各命令が1つのレイヤーになる
- レイヤーは他のイメージで再利用される（キャッシュ）
- コンテナ起動時に書き込み可能レイヤーが上に追加される

</details>

### 【中級】Docker Compose

#### Q6. Docker Composeの主な用途として、最も適切なものはどれですか？

- A) 単一コンテナのビルドを高速化する
- B) 複数のコンテナを定義・管理する
- C) コンテナイメージを圧縮する
- D) コンテナのセキュリティを強化する

<details>
<summary>回答と解説</summary>

**正解: B**

Docker Composeは、複数のコンテナで構成されるアプリケーションを定義・管理するツールです。`compose.yaml`ファイルに設定を記述し、`docker compose up`で一括起動できます。

</details>

#### Q7. 以下のcompose.yamlの問題点は何ですか？

```yaml
services:
  backend:
    build: ./backend
    depends_on:
      - db
  db:
    image: postgres:15
```

- A) 問題なし
- B) ポートが設定されていない
- C) depends_onだけではDBの準備完了を待たない
- D) イメージ名が間違っている

<details>
<summary>回答と解説</summary>

**正解: C**

`depends_on`はコンテナの起動順序のみを制御します。データベースが接続を受け付ける準備ができるまで待つわけではありません。

正しい方法：
```yaml
services:
  db:
    image: postgres:15
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 5
  backend:
    depends_on:
      db:
        condition: service_healthy
```

</details>

#### Q8. Docker Composeでサービス間の通信に使用するホスト名は何ですか？

- A) コンテナID
- B) サービス名
- C) IPアドレス
- D) localhost

<details>
<summary>回答と解説</summary>

**正解: B**

Docker Composeは自動的にネットワークを作成し、**サービス名**でDNS解決できるようにします。

例：`backend`サービスから`db`サービスに接続する場合


### 【中級】マルチコンテナ構成

#### Q9. 永続化が必要なデータベースのデータを保存するのに推奨される方法はどれですか？

- A) コンテナ内に直接保存
- B) Bind Mount
- C) Named Volume
- D) tmpfs

<details>
<summary>回答と解説</summary>

**正解: C**

| 方法 | 用途 |
|------|------|
| **Named Volume** | データの永続化（推奨） |
| **Bind Mount** | 開発時のコード共有 |
| **tmpfs** | 一時データ |

Named VolumeはDockerが管理するため、データの安全性が高くなります。

</details>

- B) コンテナの正常性を確認し、異常時に対応する
- C) コンテナのネットワークを設定する

### 【応用】本番運用

#### Q11. マルチステージビルドの主なメリットは何ですか？

- A) ビルド時間を短縮する
- B) 最終イメージにビルドツールを含めず、サイズを削減する
- C) セキュリティを強化する
- D) デバッグを容易にする

<details>
<summary>回答と解説</summary>

**正解: B**

マルチステージビルドでは、ビルドステージと実行ステージを分離します：
- ビルドステージ：コンパイラ、開発依存関係等を含む
- 実行ステージ：実行に必要なファイルのみをコピー

結果として、最終イメージのサイズが大幅に削減されます。

</details>

#### Q12. 本番環境でコンテナを非rootユーザーで実行する理由は何ですか？

- A) パフォーマンスが向上する
- B) 権限昇格攻撃のリスクを軽減する
- C) ログが読みやすくなる
- D) ネットワーク設定が簡単になる

<details>
<summary>回答と解説</summary>

**正解: B**

rootユーザーでコンテナを実行すると：
- コンテナ脱出攻撃時にホストのroot権限を取得される可能性
- 不要な権限による誤操作のリスク

非rootユーザーで実行することで、セキュリティリスクを軽減できます。

</details>

#### Q13. 以下のDockerfileの改善点は何ですか？

```dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["node", "index.js"]
```

- A) ベースイメージが古い
- B) 依存関係のキャッシュが効かない（COPYの順序）
- C) ポートが公開されていない
- D) 作業ディレクトリが間違っている

<details>
<summary>回答と解説</summary>

**正解: B**

`COPY . .`の後に`npm install`すると、ソースコードの変更のたびに依存関係が再インストールされます。

改善版：
```dockerfile
FROM node:18
WORKDIR /app
COPY package*.json ./  # 依存関係ファイルを先にコピー
RUN npm install        # 依存関係が変わらなければキャッシュが効く
COPY . .               # ソースコードをコピー
CMD ["node", "index.js"]
```

</details>

#### Q14. `restart: unless-stopped` の動作として正しいものはどれですか？

- A) コンテナは常に再起動する
- B) 手動停止以外は再起動する
- C) 異常終了時のみ再起動する
- D) 再起動しない

<details>
<summary>回答と解説</summary>

**正解: B**

| ポリシー | 動作 |
|----------|------|
| `no` | 再起動しない |
| `always` | 常に再起動 |
| `unless-stopped` | 手動停止以外は再起動 |
| `on-failure` | 異常終了時のみ再起動 |

</details>

#### Q15. Graceful Shutdownが重要な理由は何ですか？

- A) 起動時間を短縮するため
- B) 処理中のリクエストを完了させてからシャットダウンするため
- C) ログを保存するため
- D) メモリ使用量を削減するため

<details>
<summary>回答と解説</summary>

**正解: B**

Graceful Shutdown（優雅な終了）により：
- 処理中のリクエストを完了させる
- データベース接続を正しくクローズする
- データの整合性を保つ

突然の終了は、データ損失やエラーの原因になります。

</details>
