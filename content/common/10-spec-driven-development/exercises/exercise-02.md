# 課題2: 仕様書を書く

## 📋 概要

| 項目 | 内容 |
|------|------|
| 難易度 | ⭐⭐ |
| 所要時間 | 45分 |

## 🎯 目標

要件から仕様書を作成する。

## 📝 課題内容

### シナリオ

上司から以下の依頼がありました:

```
「お気に入り機能を作ってほしい。
ユーザーが商品をお気に入りに追加できて、
一覧で見られるようにしたい。」
```

### 課題2-1: 要件の明確化

上記の曖昧な要件から、確認すべき質問を5つ以上考えてください。

例:
- お気に入りの上限はありますか？
- 非ログインユーザーも使えますか？

### 課題2-2: 仕様書の作成

以下のテンプレートを使って、お気に入り機能の仕様書を作成してください。

```markdown
# お気に入り機能 仕様書

## 概要
[機能の目的と概要]

## 前提条件
[この機能を利用するための前提]

## 機能要件

### お気に入り追加
- [詳細]

### お気に入り削除
- [詳細]

### お気に入り一覧取得
- [詳細]

## API設計

### POST /api/favorites
[リクエスト/レスポンス]

### DELETE /api/favorites/:productId
[リクエスト/レスポンス]

### GET /api/favorites
[リクエスト/レスポンス]

## データベース設計
[テーブル定義]

## 非機能要件
- パフォーマンス: [要件]
- 制限: [要件]

## エラーケース
| ケース | ステータス | メッセージ |
|--------|----------|----------|
| [ケース] | [コード] | [メッセージ] |

## 画面
[必要であれば]

## 除外事項
[今回対応しないこと]
```

### 課題2-3: レビュー

作成した仕様書を以下の観点でセルフレビューしてください:

```
□ 機能要件は網羅されているか
□ API設計は RESTful か
□ エラーケースは考慮されているか
□ 非機能要件は含まれているか
□ 曖昧な表現はないか
```

## ✅ 完了条件

- [ ] 確認質問を5つ以上考えた
- [ ] 仕様書を作成した
- [ ] セルフレビューを行った
