# 課題1: 進捗報告の練習

## 📋 概要

| 項目 | 内容 |
|------|------|
| 難易度 | ⭐ |
| 所要時間 | 30分 |
| 前提知識 | コミュニケーションの基本 |

## 🎯 目標

効果的な進捗報告ができるようになる。

## 📝 課題内容

### シナリオ

あなたは「ユーザー登録機能」の実装を担当しています。以下の状況で、上司に進捗報告をしてください。

**状況**:
- 予定: 3日で完了予定
- 現在: 2日目の終わり
- 進捗: 
  - ユーザー登録フォームのUI → 完了
  - バリデーション処理 → 完了
  - データベースへの保存処理 → 作業中（70%完了）
  - メール送信機能 → 未着手
- 問題: メール送信のライブラリ選定で迷っている

### 課題1-1: 悪い進捗報告を分析

以下の進捗報告の問題点を3つ以上挙げてください。

```
お疲れ様です。
ユーザー登録機能を作っています。
だいたい順調です。
メールの部分がちょっと難しいかもです。
```

### 課題1-2: 良い進捗報告を作成

上記の状況を、以下の構成で報告してください。

```markdown
## 進捗報告: [タスク名]

### 全体進捗
- 予定: 
- 実績: 

### 完了した作業
- 

### 進行中の作業
- 

### 課題・相談事項
- 

### 次のアクション
- 
```

### 課題1-3: 遅延報告の作成

以下のシナリオで遅延報告を作成してください。

**シナリオ**:
3日目の午前中。データベース保存処理でバグが見つかり、追加で1日かかりそうです。

## ✅ 完了条件

- [ ] 悪い報告の問題点を3つ以上挙げている
- [ ] 良い報告のテンプレートを埋めている
- [ ] 遅延報告に原因と対策が含まれている

## 💡 ヒント

<details>
<summary>良い進捗報告のポイント</summary>

1. **具体的な数字**: 「だいたい」ではなく「70%」
2. **課題の明示**: 問題を隠さず報告
3. **次のアクション**: 何をするか明確に
4. **相談事項**: 判断が必要なことを明示

</details>
